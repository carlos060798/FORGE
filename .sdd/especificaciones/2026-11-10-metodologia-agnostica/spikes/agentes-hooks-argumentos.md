## S0.2 Hooks pre/post herramienta, protocolo y capacidad de bloqueo

| Herramienta | ¿Hooks pre/post? | Protocolo | ¿Puede bloquear? | Ubicación de config | Fuente (consulta 2026-11-10) |
|---|---|---|---|---|---|
| GitHub Copilot en VS Code | Sí: `preToolUse`, `postToolUse` | Comando: JSON por stdin, un objeto JSON por stdout. | `preToolUse`: sí, con `permissionDecision: "deny"` (+ `permissionDecisionReason`); error del comando se documenta como denegación; timeout cae a permisos normales. `postToolUse`: no bloquea (solo `additionalContext`). | `.github/hooks/*.json`; `~/.copilot/hooks/`; ajustes `hooks` en `.github/copilot/settings.json`; también lee `.claude/settings.json`; frontmatter `hooks` de agente. | https://code.visualstudio.com/docs/copilot/customization/hooks (2026-11-10) |
| GitHub Copilot CLI | Sí: `preToolUse`, `postToolUse` (camelCase y PascalCase compatible con VS Code) | Config `"version": 1`, hooks `type: command` con `bash`/`powershell`; JSON entrada/salida; salida con `permissionDecision` (`allow`/`deny`/`ask`), `permissionDecisionReason`, `modifiedArgs`. | Sí: `deny`; código de salida 2 deniega; otro código distinto de 0 también deniega (fail-closed); timeout es fail-open. | `.github/hooks/*.json`; `~/.copilot/hooks/*.json` | https://docs.github.com/en/copilot/reference/hooks-reference y https://docs.github.com/en/copilot/concepts/agents/coding-agent/about-hooks (2026-11-10) |
| Codex CLI | Sí: `PreToolUse`, `PostToolUse` | Handlers `command` y `mcp_tool` (los de tipo `prompt`/`agent` se parsean pero se omiten). Entrada JSON con `tool_name`, `tool_input`, etc. | `PreToolUse`: sí, `hookSpecificOutput.permissionDecision: "deny"`, `decision: "block"` heredado, o salida 2 con motivo en stderr; también puede reescribir con `updatedInput`. `PostToolUse`: no deshace efectos, puede reemplazar el resultado. La documentación indica que no es una frontera de seguridad completa. Los hooks no gestionados requieren confianza vía `/hooks`. | `~/.codex/hooks.json`, `~/.codex/config.toml`, `<repo>/.codex/hooks.json`, `<repo>/.codex/config.toml` | https://learn.chatgpt.com/docs/hooks (2026-11-10) |
| Cursor | Sí: `preToolUse`, `postToolUse`, `postToolUseFailure`, `beforeShellExecution` | Proceso con JSON por stdin y JSON por stdout. | Sí: `permission: "deny"` o salida 2. Otros códigos: fallo y la acción continúa salvo `failClosed: true`. | `<proyecto>/.cursor/hooks.json`, `~/.cursor/hooks.json`; enterprise/team | https://cursor.com/docs/agent/hooks (2026-11-10) |
| Gemini CLI | Sí: `BeforeTool`, `AfterTool` | stdin JSON, stdout solo JSON final. | Sí: `{"decision":"deny"}` con salida 0, o salida 2 (stderr como motivo). Otros códigos solo avisan. | `settings.json`: `.gemini/settings.json`, `~/.gemini/settings.json`, `/etc/gemini-cli/settings.json`, extensiones | https://geminicli.com/docs/hooks/ (2026-11-10) |
| Windsurf | sin confirmar | Las páginas de Windsurf/Cascade en docs.devin.ai no documentan eventos de Cascade; la página de hooks describe Devin Local (`.devin/hooks.v1.json`, `PreToolUse` puede bloquear, salida 2 bloquea según la visión general de Devin CLI). No es una fuente de Windsurf. | sin confirmar para Windsurf | sin confirmar | https://docs.devin.ai/desktop/cascade/hooks y https://docs.devin.ai/cli/extensibility/hooks/overview.md (2026-11-10) |
| opencode | sin confirmar (hooks vía plugins TS/JS) | La documentación abierta indica plugins en `.opencode/plugins/` y `~/.config/opencode/plugins/` y hooks V2 `execute.before`/`execute.after` (`ctx.tool.hook`); "Inspect or replace tool input before execution". Si lanzar un error bloquea: sin confirmar. | sin confirmar | `.opencode/plugins/`, `~/.config/opencode/plugins/` | https://opencode.ai/docs/plugins/ y https://opencode.ai/docs/build/plugins/server (2026-11-10) |
| Kiro | Sí: `PreToolUse`, `PostToolUse` (entre otros disparadores) | Hooks `command` o `agent`; el JSON por stdin de `PreToolUse` incluye `hook_event_name`, `cwd`, `session_id`, `tool_name`, `tool_input`. Una página indica que stdout con salida 0 se añade al contexto del agente y que otro código envía stderr al agente. | `PreToolUse`: sí, un código de salida distinto de 0 bloquea la herramienta (según la página de acciones). | `.kiro/hooks/*.json` (`"version": "v1"`); global `~/.kiro/hooks/` (CLI V3); también en config de agente (no verificado) | https://kiro.dev/docs/hooks/ , https://kiro.dev/docs/hooks/types/ y https://kiro.dev/docs/hooks/actions/ (2026-11-10) |

## S0.3 Sustitución de $ARGUMENTS / $1 en skills o comandos

| Herramienta | Comandos | Skills | Fuente (consulta 2026-11-10) |
|---|---|---|---|
| GitHub Copilot en VS Code | Prompt files: no documenta `$ARGUMENTS` ni `$1`; usa `${input:nombre}` y `${selection}`, y el texto escrito tras el comando se pasa como contexto adicional (la página no dice que VS Code lo sustituya). | No documentado en la página; sin confirmar | https://code.visualstudio.com/docs/copilot/customization/prompt-files (2026-11-10) |
| GitHub Copilot CLI | sin confirmar | No documentado en la página de skills; sin confirmar | https://docs.github.com/en/copilot/concepts/agents/about-agent-skills (2026-11-10) |
| Codex CLI | Sí, en custom prompts (`~/.codex/prompts/`): `$1`..`$9`, `$ARGUMENTS`, marcadores con nombre `$FILE` (`KEY=value`), `$$` literal. Los custom prompts están marcados como obsoletos. | sin confirmar (la página de skills devolvió 404 en la URL probada) | https://learn.chatgpt.com/docs/custom-prompts (2026-11-10) |
| Cursor | No documentado (`.cursor/commands`); sin confirmar | No documentado en la página de skills | https://cursor.com/docs/agent/chat/commands y https://cursor.com/docs/skills (2026-11-10) |
| Gemini CLI | No usa `$ARGUMENTS`/`$1`: usa `{{args}}` en TOML; sin `{{args}}`, los argumentos se añaden al final del prompt. | No documentado; sin confirmar | https://geminicli.com/docs/cli/custom-commands/ y https://geminicli.com/docs/cli/skills/ (2026-11-10) |
| Windsurf | Workflows: no documenta sustitución | No documentado | https://docs.devin.ai/desktop/cascade/workflows y https://docs.devin.ai/desktop/cascade/skills (2026-11-10) |
| opencode | Sí: `$ARGUMENTS` (cadena completa) y `$1`, `$2`... posicionales (comillas agrupan; el último absorbe el resto; los vacíos quedan en blanco). Carpeta `.opencode/commands/` y `~/.config/opencode/commands/`. | sin confirmar | https://opencode.ai/docs/commands/ (2026-11-10) |
| Kiro | No documentado para otros comandos | Solo en CLI: `$ARGUMENTS` y `${N}` (no `$1`) se sustituyen en el cuerpo del skill; en IDE y Web el texto tras el nombre se pasa como contexto, sin sustitución. | https://kiro.dev/docs/skills/ (2026-11-10) |

## Conclusión operativa

- Formato de agente: hay convergencia en Markdown + frontmatter YAML (Copilot, Cursor, Gemini, opencode, Kiro), salvo Codex (TOML). Windsurf sin confirmar.
- Hooks: el patrón común es JSON por stdin y bloqueo por salida 2 o `deny` (Copilot, Codex, Cursor, Gemini). Kiro bloquea con salida distinta de 0 según una página. Windsurf y opencode sin confirmar.
- Argumentos: solo opencode, Codex (prompts obsoletos) y Kiro (skills, solo CLI) lo documentan. Gemini usa `{{args}}`. No se debe asumir `$ARGUMENTS`/`$1` como mecanismo portable.
